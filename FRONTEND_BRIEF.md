# RaceIQ — Frontend Brief & Antigravity Prompt

## 0. Who we are: **RaceIQ is the Haas pit wall**

RaceIQ is presented as the **Haas F1 Team** race-engineering tool. Every
recommendation is made **for a Haas car** — OCO (#31) or BEA (#87) — against the
car directly ahead. The UI must never present a generic "P3": it must say
*whose* call this is.

- `meta.our_team` = `"Haas F1 Team"`
- `meta.our_cars` = `["OCO", "BEA"]`
- `meta.focus` = the car we are advising right now
- `meta.teammate` = the other Haas car
- `meta.ego` = `focus`; `meta.rival` = the car ahead of it

Both the lineup (drivers, teams, official colours, car numbers) and the running
order come from **real cached 2026 FastF1 data**, not invented placeholders.

## 1. Why a separate frontend (and why Streamlit stays)

Streamlit is a script that re-runs on every interaction — it has **no render
loop**, so it cannot smoothly animate. That is fine for the spec-compliant
deliverable (spec §3.4 mandates Streamlit), but wrong for a showpiece. So:

- **Keep the Streamlit app** as the spec-mandated, reproducible, testable backend.
- **Build a separate animated frontend** (fed the JSON contract below) as the demo.

> **All energy / SoC numbers are ESTIMATES.** No public ERS/SoC telemetry exists.
> The frontend **MUST** always render `meta.watermark`. Prior art: arXiv:2603.01290.

## 2. Data contract

### Fixtures (already generated by `src/raceiq/ui/contract.py`)

For each of the **five demo circuits** (`Melbourne`, `Shanghai`, `Monza`,
`Bahrain`, `Baku`) there are three ready-to-use grids — **17 JSON files total**:

| File | Meaning |
|------|---------|
| `data/grid_<circuit>_real.json` | The **real** 2026 grid, untouched (`grid_edited: false`) |
| `data/grid_<circuit>_battle.json` | Our Haas car brought inside the Detection Gap (`grid_edited: true`) → live bet |
| `data/grid_<circuit>_battle_trap.json` | Battle + counter-harvest trap → **HOLD** |

Plus `data/sample_scenario.json` (Melbourne battle, **GO**) and
`data/sample_scenario_trap.json` (**HOLD**) — the two headline frames.

**Grid provenance is explicit** so nothing is ever passed off as measured:

| `meta` field | Meaning |
|---|---|
| `data_status` | `cached_2026` \| `no_fastf1_telemetry` \| `not_raced_yet_2026` |
| `simulation_only` | true for Baku (not raced in 2026) — **must be labelled SIMULATION** |
| `grid_source` | `fastf1_cache` (real) \| `canonical_lineup` (fallback) |
| `grid_edited` | true when the analyst moved cars / overrode a gap |
| `grid_note` | human-readable provenance string |

### Top-level keys

| Key | Type | Meaning |
|-----|------|---------|
| `meta` | object | event, lap, total_laps, window_mj, detection_gap_s, circuit_harvest_potential_mj, ego, rival, **our_team, focus, teammate, our_cars**, **data_status, simulation_only, grid_edited, grid_source, grid_note**, watermark, prior_art |
| `grid` | array[22] | The full running order: `position, code, driver, name, team, colour, number, pace_s, interval_s, gap_ahead_s, is_ours` |
| `working` | object | **The calculations** — see below |
| `tower` | array[22] | Timing tower row: `position, driver, team, colour, interval_s, lap_delta_s, est_soc_mj, est_soc_pct, mode` |
| `ego_row` / `rival_row` | object | Our car and the car directly ahead |
| `belief` | object | 8-state HMM posterior: `probs[8]`, `p_ers{H,M,Lharvest,Lderate}`, `p_overtake_available`, `trap_prob`, `trap_flag`, `dominant_ers`, `evidence` |
| `decision` | object | `go` (GO/HOLD), `recommendation` (ATTACK/HOLD/HARVEST/DEFEND), `p_pass`, `ev`, `trap_flag`, `eligible`, `gap_s`, `why`, `breakdown_*` |
| `posture` | object | Tier-2 MPC: `posture`, `rationale`, `per_lap_net_mj[]`, `min_soc_mj`, `horizon_laps` |
| `compliance` / `compliance_rows` | object / array | FIA ledger: `passed`, `violations[]`, `checks{}`, `details{}`, `measured{}`; rows `{rule, status, detail}` |
| `frontier` | object | Tier-1 Pareto price list: `energy_mj[]`, `lap_time_s[]`, `exchange_rate_s_per_mj`, `max_energy_mj` |
| `comparison` | object | **With vs without RaceIQ**: `best_strategy`, `by_total_time[]`, `rows[]` (Greedy / Conservative / RaceIQ) |
| `soc_history` | object | `lap[]` + one float[] per driver — estimated SoC trajectory |
| `speed_trace` | object | `Distance[]`, `Speed[]`, `Throttle[]`, `dSpeed[]`, `clipping[]` |

### `working` — the "show your working" panel

Judges must be able to follow every number. `working` exposes the whole chain:

```
chain[6]              # the 6-stage pipeline, plain English
ev_formula            # "EV = P(pass) x points_gain - repass_cost - repayment - lambda x illegal"
ev_terms              # p_pass, points_gain, repass_cost_pts, repayment_pts, illegal_penalty, ev
decision_rule         # "GO when EV > 0 AND eligible AND legal AND not trap; otherwise HOLD"
eligibility           # gap_s, detection_gap_s, eligible
trap_test             # p_Lharvest, p_Lderate, trap_prob, trap_flag, p_overtake_available
price_of_energy       # exchange_rate_s_per_mj, max_energy_mj, window_mj
battery_estimate      # ego/rival SoC (MJ + %) — flagged ESTIMATED
compliance_measured   # measured value per FIA rule (net_mj, deploy_mj, peak_power_kw, ...)
```

### Animation hooks

- **Car positions**: place car `i` by arc-length — leader at `s=0`, car `i` at
  `clamp(interval_s_i / max_interval, 0, 1)` of the lap. Drive a looping
  lap-progress `p(t)` (0→1 over ~90 s) and render at `(offset_i + p) mod 1`.
- **Overtake**: `decision.go == "GO"` → ego closes on the rival and swaps ahead.
  `decision.trap_flag` → red **TRAP** pulse on the rival instead.
- **Gauges**: `ego_row.est_soc_pct` → ERS/SoC arc; `belief.p_ers` → four bars;
  `decision.p_pass` → probability meter.
- **Decision card**: flip/scale on `go` (GO green, HOLD amber).

### Racecast — the full-race simulation (THE MAIN VIEW)

`data/racecast_<circuit>.json` for Melbourne / Shanghai / Monza. This replays a
**previous race with all 22 drivers on that day's real grid**, lap by lap, and is
what the judges watch.

```
{
  circuit, total_laps, our_team, data_status, simulation_only, watermark, prior_art,
  laps: [                     # one entry per lap, in order
    {
      lap: int,
      cars: [                 # ALL 22 cars — this is the hover data
        { code, name, team, colour, number, position,
          interval_s, gap_ahead_s,
          est_soc_mj, est_soc_pct, mode,        # ESTIMATED
          speed_kph, throttle, brake, clipping, lap_time_s, is_ours }
      ],
      haas: [                 # the PINNED pair — always on screen
        { code, team, colour, position, interval_s, gap_ahead_s,
          est_soc_mj, est_soc_pct, mode, speed_kph, throttle,
          action, go, eligible, p_pass, ev,
          reward_pts, risk_pts, risk_reward,    # the RISK / REWARD ratio
          trap_flag, rationale }
      ]
    }
  ]
}
```

- **Hover any car** → show its `est_soc_pct`, `mode`, `speed_kph`, `throttle`,
  `clipping`, `interval_s`, `lap_time_s` from that lap's `cars[]` entry.
- **Pin the Haas pair** from `haas[]` — always visible, updating every lap:
  SoC arc, position, gap ahead, **risk / reward ratio**, and the **action**.
- `risk_reward = reward_pts / risk_pts` where `reward_pts = P(pass) x points_gain`
  and `risk_pts = repass_cost + repayment`. Show it as a badge:
  **> 1.0 = worth it (green), < 1.0 = don't (amber)**.
- **Action button** = `haas[i].action` (ATTACK / HOLD). Style it as a real pit-wall
  button: green "ATTACK" when `go == "GO"`, amber "HOLD" otherwise, with the
  `rationale` string beneath it.

## 4. Backend notes

- Real grids come from `src/raceiq/ui/grid.py`: lineup from cached FastF1
  `driver_info`; **order** = real median lap-time ranking; **gaps** = pace
  deficit × laps. Circuits without telemetry fall back to the canonical 2026
  entry list and are flagged.
- `build_scenario(event, ..., our_team, focus, grid, focus_gap, trap)` builds a
  frame; `scenario_to_frontend()` serialises it.
- Regenerate fixtures any time with:
  `PYTHONPATH=src python src/raceiq/ui/contract.py`

## 5. Known issue

`tests/test_tier1_dp.py::test_dp_under_10ms_on_real_circuit` is a **timing
flake** under full-suite load (median ~16 ms when the machine is busy; passes in
isolation at <10 ms). It is unrelated to the UI work — the DP itself is correct.
